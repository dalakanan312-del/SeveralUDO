SEVERALUDO CLOCK SYNC 2.2.5 - TROUBLESHOOTING
================================================

RECEIVER SAYS WAITING
- Confirm config.json is in Mods\SeveralUDOClockSync beside the .ts4script.
- Double-click Start SeveralUDO Clock Relay.bat.
- Load a household in Live Mode and let the game clock advance. If needed, change lots once.
- A report is not generated while the game is fully paused on menus.

THE BAT FILE FLASHES AND CLOSES
This is normal. The starter launches the PowerShell relay in a hidden window. Starting it again is safe; a mutex prevents duplicate relays.

THE POWERSHELL RELAY OR BAT FILE IS MISSING
- Open the SeveralUDOClockSync folder inside the ZIP; do not look only at the ZIP's top level.
- Extract the entire folder before checking it.
- If Windows security filtered a command file, rename SeveralUDOClockRelay.ps1.backup.txt to SeveralUDOClockRelay.ps1 and Start SeveralUDO Clock Relay.bat.backup.txt to Start SeveralUDO Clock Relay.bat.
- You can also download both files individually from the tracker Game Clock page.

REPORT_QUEUE CONTAINS FILES
This is the ordered offline queue. Open relay_health.json and last_result.json. Common causes are no internet, a stopped local tracker, an expired token, or an incorrect receiver URL. Reports remain oldest-first and are removed only after tracker acknowledgement. Fix the cause and leave the relay running.

REPORT_QUARANTINE CONTAINS A FILE
The tracker permanently rejected that report, normally because its checksum failed or it came from a different Sims save slot. Nothing from that report changed the tracker. If the different save was intentional, open Game Clock, choose Trust the next reported Sims save, return to Live Mode, and let time move.

WRONG SIMS SAVE WAS REJECTED
This is the expected save-slot protection. Load the paired game save, or explicitly clear the pairing on the tracker Game Clock page before trusting a different slot. Never clear it merely to make an unfamiliar report disappear.

THE MOD DOES NOT APPEAR AT GAME START
- Confirm Script Mods Allowed is enabled.
- The .ts4script must be no more than one folder beneath Mods.
- Remove duplicate older SeveralUDOClockSync.ts4script copies.
- Delete localthumbcache.package after closing the game if The Sims 4 is still loading an old copy.

SKILLS OR MILESTONES ARE MISSING
- Confirm the Game Clock page offers Clock Sync 2.2.5 or newer.
- Close The Sims 4, replace SeveralUDOClockSync.ts4script, then restart the game.
- Enter Live Mode with the affected played household and let one Sim minute pass.
- Skills are included after level 1. Completed milestones require Growing Together; a missing pack is handled safely.
- Open the Sim's profile to see the synchronized Skills and Milestones sections.

MODGUARD OR SECURITY SOFTWARE SHOWS A WARNING
Clock Sync 2.2.5 does not make the HTTPS request from inside The Sims 4. The Script Mod writes checksummed JSON files to report_queue; SeveralUDOClockRelay.ps1 sends them. Its temporary local save also remains a JSON file so ModGuard can validate it. Only use files downloaded from your tracker. Do not approve a differently named executable or script.

REPORT SUCCEEDS BUT THE TRACKER STILL SAYS WAITING
- Refresh the Game Clock page.
- Confirm the endpoint in config.json belongs to the tracker edition you are viewing.
- Check last_result.json: ok=true and receiver_ok=true confirm acceptance.
- If you replaced the private link after installing config.json, download the new config again.

THE TRACKER DAY IS MISALIGNED
Use Repair alignment from the last report on the Game Clock page. It pairs the last reported game day with the current tracker Global Day without editing Sims or rewinding the game.

GAME WAS OPENED BEFORE THE RELAY
You normally do not need to restart. Start the relay, return to Live Mode, and let time advance or change lots. Restart the game only after replacing the .ts4script or when the mod was not loaded.

SAFE FILES TO SHARE FOR SUPPORT
- README - Install Clock Sync.txt
- TROUBLESHOOTING.txt
- A redacted last_result.json or relay_health.json with private URLs/tokens removed

NEVER SHARE config.json, sync_token, a private configured kit, or queued report files.
